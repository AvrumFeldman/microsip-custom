MicroSIP Custom 3.22.16.6 - Windows voice calls
============================================

This is an independently maintained fork, not an official MicroSIP release.
Download/update: https://github.com/AvrumFeldman/microsip-custom/releases
Source and public PRs: https://github.com/AvrumFeldman/microsip-custom
PRs are welcome and appreciated, including AI-assisted and AI-generated ones.

Start
-----
Extract to a writable folder and run microsip.exe. Keep MicroSIPAudioGuard.exe
beside it. Custom builds reuse accounts/settings/contacts/history under
%APPDATA%\MicroSIP Custom, with logs/new recordings under %LOCALAPPDATA%\MicroSIP Custom.
For the first upgrade from an older custom portable copy, close it and put
the new application files into that existing custom folder. On launch its
accounts, passwords, contacts and history migrate once without deleting the
originals. Later builds reuse the shared profile, even from another folder.
Release ZIPs contain no live microsip.ini that could overwrite your accounts.
Create an empty microsip.portable file beside the exe for explicit portable
mode. That copy continues using its adjacent accounts/settings/databases.
Only a first migration from official MicroSIP needs account/password entry:
the public source omits the official password encryption key. Custom account
passwords are preserved between custom builds.

Updates
-------
Menu > Check for updates uses stable releases from our GitHub repository.
Checks default to daily; Settings controls the interval. Download/restart
requires confirmation. The updater verifies archive/file checksums and waits
for all calls to end before replacing application files. Accounts, contacts,
history, recordings and existing sounds are preserved. Failed replacement
attempts restore backed-up files when possible. Official MicroSIP update
checks and the inherited build-age expiration are disabled in this build.

Audio changes
-------------
Entering digits and incoming ringtones use playback only. Incoming early
media cannot activate capture before you answer. Incoming ringing alone
does not grab capture or mute music. Capture is released after the final call ends, even
before a remote SIP hangup acknowledgment. Periodic state reconciliation
cleans up stale microphone ownership.

Incoming-call windows are shown without activation. With bring-to-front
enabled they appear in front while focus stays in your current app, avoiding
Windows' pointer snap to a newly activated dialog button.

Menu > Settings > Other audio during calls offers:
  Leave other audio unchanged (default)
  Mute all other apps
  Mute selected apps
For selected apps use names such as Spotify.exe; vlc.exe, or Add app...
Matching is case-insensitive. A browser name affects the whole browser.

Muting begins when dialing an outgoing call or answering an incoming call,
and continues through hold/overlapping calls. After the final call, capture
closes first; Bluetooth Classic call audio must then report its actual SCO
disconnect before music resumes. There is no fixed unmute delay or list of
supported headset models. Devices are discovered dynamically through Windows.
Apps already muted stay muted; volume levels are unchanged. A manual unmute
during the call or recovery takes precedence, including a later manual re-mute.
Only mutes applied by MicroSIP are restored. A new call during recovery keeps
the existing mute ownership without briefly restoring music. Helpers from
restarted copies also coordinate their holds.
New audio sessions are detected periodically. MicroSIP and system sounds
are excluded. The audio guard keeps the same checks if MicroSIP crashes/exits.
Unknown transport state keeps audio muted. Menu > Restore other audio now
explicitly restores MicroSIP-owned mutes; the guard also provides restoration
after the main app exits. Unresolved devices and LE Audio require manual
restoration. Wired/USB audio restore after capture closes. A wireless dongle
exposing only USB audio hides its internal profile state, so this build cannot
wait for that internal transition. The guard cannot restore if it is itself
killed or Windows audio fails.
Exclusive-mode players may not follow Windows session mute controls.

Calls
-----
SIP registration retries use bounded delays (5-10 seconds for native retries,
25 seconds for other failures), with no growing backoff.

Answering a second incoming call in single-call mode holds the first call.
Hold opens a menu even with one connected call. Choose Hold current call,
Resume current call, New call, or Switch to another connected caller.
Settings > Hold before a new call controls when the first party is held:
when you press Call (default) or when you choose New call. Dialing waits
for the hold response. Switching holds the current party before resuming
the selected party.
Incoming history also records unnamed callers and calls rejected by DND or
concurrent-call limits. A conflicting Windows startup entry prompts to switch
to this custom executable; declining preserves the existing entry.

CONF > Add participant / Remove participant works in single-call mode.
Choose the participant to remove; only that conference leg is disconnected.

Transfer's dropdown offers Blind Transfer and Attended Transfer (consult
first). For attended transfer enter the destination and confirm, speak to
the destination, then select Complete attended transfer. Cancel consultation
and return resumes the original held call. End also cancels a consultation,
even while ringing. Calls routed back to the same account have separate
Answer/Decline controls and preserve the original held call when answered.
PBX/provider support for SIP
REFER with Replaces is required. Existing PBX feature-code settings remain
available.

A forced process termination cannot send SIP hangup messages. The remote
call may remain until the other party hangs up or the PBX detects the lost
session. The audio guard restores Windows audio, not SIP calls.

Build differences and validation
--------------------------------
The dialer hides messaging and video quick buttons for this calls-only
build, while retaining their source code. It uses a full-width Call button
and keeps the number field near the tabs instead of adding blank top space.
Windows taskbar identity and icon fallbacks are explicitly set.
Name/number separators in the separate call window display correctly.

Based on published MicroSIP 3.22.16 source, not the newer official 3.22.18
binary. Voice only; WAV recording; PJSIP audio codecs plus Opus. No video,
official MP3 recorder, or external G.729/AMR/SILK/G.722.1 codecs. TLS and
SRTP/DTLS are included. The executables are unsigned.
PJSIP includes public MP3 writer source, but its stock recorder does not
wire that writer to an encoder. MP3 needs integration and recording tests;
WAV-only is this custom build's limitation, not a licensing requirement.

XML/regex helpers with restrictive bundled-source notices were replaced;
an unused message-box helper was removed. Original upstream authorship
and applicable license notices are preserved.

Regression tests use synthetic local SIP calls, silent Windows render
sessions and account-free test data. A hardware check confirmed that the Windows
observer waited for an actual SCO disconnect after capture closed. Other driver
and headset combinations, audio quality, and provider/PBX compatibility still
require a check on your setup.
See README.md for build commands, test prerequisites and detailed behavior.
